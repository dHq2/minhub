## 1. 도감이 그림을 저장하는 방식

base64 로 박아 넣은 그림은 없음. 전부 게시 파일 · 자산 보관함의 webp/png 를 경로로 부름.

- catalog.js: `const CATALOG = [...]` 그림 5737개 (인물 char 3079 · 장비 687 · 가구 918 · 스킬 · 이야기 card 348 · 장면 scene 283 · 일반 item 293 · 유물 129). 항목마다 id · cat · sub (묶음) · name · src (그림 경로) · note · on (게임에 들어감) · cid (인물 번호 C-xxx) · parent (접힌 변형 · 표정) · game (게임 속 쓰임).
- packs.js: 게시 파일 수 한도 (511) 때문에 작은 그림은 묶음 시트 pack/*.webp 79장에 모아 둠. `PACKED[src] = [시트 번호, x, y, w, h]`. 페이지의 picUrl() 이 canvas 로 잘라 씀.
- hipacks.js: 꽉 찬 화면 (스샷) 용 원본 해상도. `HI[src] = [hi 시트 번호, x, y, w, h]`, 시트는 hi/hi0~hi34.webp.
- blobs.js: 무거운 그림 (hi 시트 35장 · 움짤 102장) 은 도감 자산 보관함 (1GiB) 에 있음. `BLOBS[경로] = 자산 id`, 페이지는 `/_blob/<id>` 로 읽음. Artifact read 의 path 에 자산 id 를 하나씩 넣어 받을 수 있음 (paths 로 여러 개는 안 됨).
- 낱장 파일: img/char/*_art.webp (원화), img/old2d/*_face.webp (2D판 얼굴), img/talk/*.webp (대화 표정), a/skills/*.png (2D판 스킬 아이콘) 등.
- 인물 설정 · 구분 · 등급은 그림 파일이 아니라 도감 공유 저장소 (db) 의 marks 컬렉션, 문서 id = 인물 번호. 필드: cspec (인물 공통 설정 = 설정 원문), role (펫 · 동료 · NPC · 적), tier (1~7 등급), name (바꾼 이름), face (고른 대표 초상화), recruit (영입 가능), group (무리), status (등장).
- 등급 눈금 (index.html TNAME): 1 잡몹 · 2 중몹 · 3 강적 · 4 중간보스 · 5 보스 · 6 최강 · 7 초월. 펫 · 동료는 같은 눈금을 ★1~★7 로 읽음.

## 5. 전투판의 faces.webp · faces_idx.json 은 어떻게 만들었나

- faces.js (node): 그때 받은 catalog.js · packs.js 와 저장소 스냅샷 codex_db2/marks 를 읽어, 인물 (cid) 마다 대표 얼굴 하나를 고름 — 저장소의 face (고른 대표) → 삭제 표시 안 된 초상화 (id 가 F- 로 시작하거나 -face 로 끝남) → 삭제 표시 안 된 아무 그림 → 첫 그림. 결과를 facemap.json 에 씀 (cid → {id, src, face, pack:[시트, x, y, w, h] 또는 null}).
- atlas.py (python, PIL): roster.json 순서대로 247명을 돌며 pack 시트에서 잘라내거나 낱장을 열고, 알파 (16 넘는 곳) 의 bbox 를 구해 초상화면 bbox 중심 정사각형, 서 있는 그림이면 위쪽 정사각형 (머리 부분) 을 잘라 80px 로 줄여 16칸 격자에 붙임 → build/faces.webp (webp 품질 86), build/faces_idx.json {S:80, COLS:16, idx: cid → 칸 번호}. roster4.json 순서와 칸 번호가 같음.
- build10.py: page10.tpl.html 에 엔진 (rt3.js) · roster4.json · faces_idx 의 {S, COLS} 를 끼워 build/gul-battle.html 을 만듦. faces.webp 는 전투판 게시 파일로 따로 올라가 있고, 페이지는 background-position 으로 칸을 집음 (faceCss · atlas 이미지).
- e63d.py 는 버전 문자열만 바꾸는 편집 스크립트 (아틀라스와 관계 없음).
- 요청한 26명은 모두 이미 아틀라스에 들어 있음 (칸: 카리우스 0 · 친칠라 10 · 산딸기 18 · 탕아 19 · 인주 22 · 레베카 23 · 모닝스타 24 · 노먼 25 · 옐로 26 · 잭 34 · 청광묵 35 · 가윤 36 · 트라카 37 · 간두 41 · 나달 44 · 청갑 66 · 아이텐 80 · 세자르 142 · 각혈 143 · 호레이쇼 160 · 곤봉 거한 164 · 붉은 망토 궁수 165 · 검사 175 · 창병 176 · 검방패병 177 · 똥개 190). 다만 10-10 판이라 모닝스타 · 옐로는 2D판 얼굴, 각혈은 옛 초상화, 친칠라는 10-10 다시 자르기 전 얼굴일 수 있음.

같은 방법으로 표정을 뽑을 수 있나
- 모닝스타 얼굴 표정 4장: 그대로 됨. 같은 pack/face1.webp 안에 있고 packs.js 좌표로 자르면 끝 (atlas.py 의 pack 분기와 같음).
- 대화 표정 (친칠라 10 · 모닝스타 3 · 오딜 5): pack 이 아니라 낱장 img/talk/*.webp 라 자를 필요 없이 받으면 됨. 다만 흰 바탕 RGB 라서, 어두운 전투판에 올리려면 바탕을 지워야 함 (이번 추출에서 지움).
- 원본 해상도가 필요하면 hipacks.js → blobs.js 로 자산 보관함의 hi 시트를 받아 자름 (2기 초상화 160 → 256, 원화 280x420 → 600x900).
- 주의: atlas.py 가 읽는 artifact-files/19b948dc-6a33-4150-9b19-956f18dac694/ 의 catalog.js · packs.js 는 이번 조사에서 Artifact read 기본 저장 위치로 받으면서 최신 판 (v1.96) 으로 바뀌었는데, 같은 폴더의 pack/face0 · face1 · h3x0 · npc2~7.webp 는 10-10 옛 판 그대로임 (face1 은 2896 → 3412 줄로 커졌고 좌표가 바뀜). 그 폴더로 faces.js → atlas.py 를 다시 돌리면 엉뚱한 곳을 자름. 다시 만들 때는 dogam_src/pack/ 의 최신 face0 · face1 (과 필요한 다른 시트) 을 쓰거나 그 폴더로 복사한 뒤 돌릴 것.
