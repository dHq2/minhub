# 세희 방들 사이 연락 통로 — v2 (2026-11-13)

방이 셋이다. 파일은 '보낸 쪽'마다 하나 — 한 파일은 한 방만 쓰니 두 방이 같은 줄을 동시에 고칠 일이 없다.

| 방 | 맡은 것 | 고치는 폴더 | 이 방만 쓰는 파일 | 버전 | 이름 앞머리 |
| --- | --- | --- | --- | --- | --- |
| 메인 | 세희 본체, 배포, 계정 서버, 창구(SEHEE) | sehee/(bonus·bonus-c 빼고), sehee-sync/ | from-main.md | v1.x | — |
| 보너스 B (제작기 2) | 보너스 기능 | sehee/bonus/ | from-b.md | B0.x | 키·도구 b_, CSS·id b- |
| 보너스 C (제작기 3) | 보너스 기능 | sehee/bonus-c/ | from-c.md | C0.x | 키·도구 c_, CSS·id c- |

읽기·쓰기 순서
1. 일을 시작할 때: `git pull --rebase` 후 남의 from 파일 둘을 다 읽는다. 나에게 온 새 항목(받는 쪽에 내 이름이나 '모두')이 있으면 보스에게 첫 답에서 한 줄로 알린다.
2. 새 기능을 시작하기 전: 남의 '## 지금 맡은 일'과 겹치는지 본다. 안 겹치면 내 파일 '## 지금 맡은 일'에 먼저 적고 올린다(찜). 겹치면 시작하지 말고 보스에게 묻는다.
3. 올리기 직전: 다시 `git pull --rebase`, 남의 from 파일을 다시 읽는다. 내 폴더와 내 from 파일만 커밋. 강제 푸시 금지.
4. 처리한 항목은 남의 파일이 아니라 내 파일에 `처리함: 날짜 · 그쪽 항목 제목` 한 줄.

항목 양식
```
## YYYY-MM-DD HH:MM · 제목 · [급함/보통/참고] · 받는 쪽: 메인/B/C/모두
- 무엇: 한두 줄
- 왜: 한 줄
- 받는 쪽에게 필요한 일: 한 줄 (없으면 "없음, 참고")
- 관련 파일·버전: 본체 v1.4.0 / B0.5 / C0.1 등
```

다툼이 생기면
- 같은 화면·같은 기능을 두 보너스가 건드리게 되면 먼저 찜한 쪽이 하고, 다른 쪽은 창구 요청이나 보스 판단을 기다린다.
- 보너스끼리는 서로의 코드·DOM·저장 키를 직접 부르지 않는다. 필요하면 메인에 창구 요청 → 메인이 SEHEE 에 열어 준다.
- 본체를 바꿔야 하는 일은 무조건 메인. 보너스는 본체 파일을 고치지 않는다.

비밀번호·PIN·API 키·학생/학부모 개인정보는 절대 적지 않는다(이 저장소는 공개다). 예전 to-main.md / to-bonus.md 는 옮겨짐 표시만 남겼다.
