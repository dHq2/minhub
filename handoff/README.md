## 일하는 순서 (v4)
1. 시작: `git pull --rebase` → 할일.md 와 남의 from 파일 두 개를 읽는다(처리 끝난 알림은 각 방이 from-X-보관.md 로 옮겨 짧게 유지). 나에게 걸리는 새 알림이 있으면 보스에게 첫 답에서 한 줄로.
2. 찜: 할일.md 에 한 줄(`맡음:`·`파일:`) 쓰고 바로 올린다 — `TESTS=none bash tools/ship.sh A "할일: 찜 …"` 대신 문서만이면 그냥 `git commit && git pull --rebase && git push` 도 된다(할일.md 는 union 합치기라 충돌 안 남).
3. 작업: 찜한 파일을 직접 고친다. 남에게 부탁하고 기다리는 일은 없다.
   - 번호를 쓰지 않는다: index.html APP_VERSION · sw.js VERSION · CHANGELOG 맨 위는 손대지 않는다.
   - 코드 주석에 본체 번호 대신 날짜·방: `/* 11-15 A: … */`.
   - 새 스타일은 css/(내 방).css. app.css 는 고칠 때만(맨 아래에 덧붙이지 않는다).
   - 변경 설명은 changes/(내 방).md 에 '- ' 줄로.
4. 검사(빠른 길): 바꾼 기능의 테스트만 먼저 — `bash tests/run.sh tregen tdel` (tcode·tload 는 늘 같이 돈다). 출력 줄을 직접 읽고, 바꾼 화면 스크린샷을 본다.
5. 올리기: `SHIP_TRAILER='Claude-Session: …' bash tools/ship.sh A "한 줄 요약"`
   - 기본은 전체 검사(동시에 3줄, 약 6분)를 한 번 돌리고 올린다. 밀려서 남의 코드가 들어오면 그때만 다시 돈다.
   - 가벼운 길(동작이 안 바뀌는 문구·색·간격·문서): `TESTS="그 화면 테스트" bash tools/ship.sh …`. 문서·할일·알림만: `TESTS=none`.
   - 강제 푸시 금지. 충돌로 멈추면 손으로 풀고 ship.sh 를 다시.
6. 끝: 할일.md 줄을 `[x]` 로(끝난 일 맨 위), 남의 일에 걸리는 게 있으면 내 from 파일에 알림.

## 시간 줄이는 약속 (v4, 세 방 검수 B·C 의견 종합)
- 전체 검사는 올릴 때 한 번(ship.sh). 작업 중엔 관련 테스트만.
- 테스트 스크린샷은 /tmp 로만(tests/*.png 는 .gitignore). 새 테스트는 고정 기다림(waitForTimeout) 대신 상태 기다림(waitForSelector·waitForFunction).
- 보스가 기다리는 동안엔 생각을 짧게: 작은 요청은 바로 손대고, 큰 결정만 묻는다.
- 실주소 확인은 기다리지 말고 다음 일을 먼저, 끝에 한 번(https://dhq2.github.io/minhub/ 에서 fetch).

## 할일.md 한 줄 양식
```
- [ ] 일감 이름 · 맡음: 없음/A/B/C · 파일: js/office.js, css/app.css · 보스 요청: 11-13 · 메모(짧게)
```

## 알림 항목 양식 (from-*.md)
```
## YYYY-MM-DD HH:MM · 제목 · [급함/보통/참고] · 받는 쪽: A/B/C/모두
- 무엇: 한두 줄
- 받는 쪽에게 필요한 일: 한 줄 (없으면 "없음, 참고")
- 관련 파일·버전: 파일 이름 / 올린 번호(ship.sh 가 알려 준 것) / tests 등
```
처리한 알림은 내 파일에 `처리함: 날짜 · 그쪽 항목 제목` 한 줄.

## 부딪칠 때
- 같은 파일: 먼저 찜한 방. 꼭 같이 해야 하면 파일 안에서 함수 단위로 나눠 할일.md 에 적는다.
- 판단이 갈리면 보스가 정한다. 방끼리 서로 지시하지 않는다.
- 본체를 크게 들어내거나 옮길 때(파일 쪼개기, 이름 바꾸기)는 할일.md 에 [급함] 으로 알리고 다른 방은 그 파일을 쉰다.
