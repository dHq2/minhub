# 세희 세 방 연락 통로 — v3 (2026-11-13)

v3 부터 세 방은 위아래 없는 동등한 작업자다. 위에는 보스(민수)만 있다. '메인'·'보너스' 구분은 없앴다.
방 이름: A(옛 메인 방) · B(제작기 2) · C(제작기 3). 자세한 공통 맥락은 프로젝트 자료 「claude/세희-인수인계-v3.md」.

## 파일
| 파일 | 누가 쓰나 | 무엇 |
| --- | --- | --- |
| handoff/할일.md | 세 방 모두(자기가 맡은 줄·새 줄만) | 일감 목록 + 찜. 여기가 유일한 찜 자리 |
| handoff/from-a.md · from-b.md · from-c.md | 그 방만 | 알림: "내가 바꾼 것 중에 남의 일에 걸리는 것" |

from-main.md 는 from-a.md 로 이름이 바뀌었다(옛 글 그대로). to-main.md · to-bonus.md 는 옛 통로(읽기만).

## 일하는 순서
1. 시작: `git pull --rebase` → 할일.md 와 남의 from 파일 두 개를 읽는다. 나에게 걸리는 새 알림이 있으면 보스에게 첫 답에서 한 줄로.
2. 찜: 보스가 시킨 일을 할일.md 에 한 줄로 적고(없으면 새로), `맡음: 방` 과 `파일:` 을 채워 바로 올린다. 남이 같은 파일을 찜해 두었으면 시작하지 않고 보스에게 묻거나 일을 나눈다. 둘이 동시에 같은 줄을 찜하면 git 충돌이 난다 — 먼저 올라간 쪽이 이긴다.
3. 작업: 찜한 파일은 본체든 실험 파일이든 직접 고친다. 남에게 부탁하고 기다리는 일은 없다.
4. 검증: `bash tests/run.sh` 전부 통과 + 바꾼 기능은 화면 스크린샷을 직접 본다(인수인계 v3 의 5단계).
5. 올리기 직전: 다시 `git pull --rebase`. 본체를 고쳤으면 버전 = 방금 받은 최신 + 1 (index.html 의 APP_VERSION 과 sw.js 의 VERSION 두 곳, 같게), CHANGELOG.md 맨 위에 한 항목. 강제 푸시 금지.
6. 끝: 할일.md 의 그 줄을 `[x]` 로, 남의 일에 걸리는 게 있으면 내 from 파일에 알림 한 항목.

## 할일.md 한 줄 양식
```
- [ ] 일감 이름 · 맡음: 없음/A/B/C · 파일: js/office.js, css/app.css · 보스 요청: 11-13 · 메모(짧게)
```

## 알림 항목 양식 (from-*.md)
```
## YYYY-MM-DD HH:MM · 제목 · [급함/보통/참고] · 받는 쪽: A/B/C/모두
- 무엇: 한두 줄
- 받는 쪽에게 필요한 일: 한 줄 (없으면 "없음, 참고")
- 관련 파일·버전: 본체 v1.5.1 / tests 등
```
처리한 알림은 내 파일에 `처리함: 날짜 · 그쪽 항목 제목` 한 줄.

## 부딪칠 때
- 같은 파일: 먼저 찜한 방. 꼭 같이 해야 하면 파일 안에서 함수 단위로 나눠 할일.md 에 적는다.
- 판단이 갈리면 보스가 정한다. 방끼리 서로 지시하지 않는다.
- 본체를 크게 들어내거나 옮길 때(파일 쪼개기, 이름 바꾸기)는 할일.md 에 [급함] 으로 알리고 다른 방은 그 파일을 쉰다.

비밀번호·PIN·API 키·보스 개인 정보·학생/학부모 개인정보는 절대 적지 않는다(이 저장소는 공개다).
