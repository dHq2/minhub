# 설계 — 판 → 일간보고서 (시각 단위 판 · 지난 판 · 세희 코멘트) — v1.1 (2026-11-14, A)

보스 요청(11-14 05:50): 판을 일간보고서로 개명. 큰 갱신 때와 날이 바뀔 때만 새 판(시각 단위 이름), 작은 수정은 그 판 안에서. 지난 판은 저장되고 참조된다. 세희가 직접 쓴 느낌의 코멘트(너무 길지 않게).
보스: "지금 우리 일간보고서 업데이트 방식을 적극 참고" → 원파인 일간보고 스킬(v34)의 규칙을 앱에 옮긴다.
보스: "설계만 해놓고 C가 끝나면 해도 좋아" → C 의 '판 보편화'(base.js·ai.js 같은 파일)가 올라간 뒤 A 가 구현한다.

## 1. 실제 일간보고 방식에서 가져오는 규칙
| 실제 방식(스킬 v34) | 앱에서 |
| --- | --- |
| 날마다 새 판 — 그날 첫 저장은 새 문서, 보스가 말 안 해도 날이 바뀌면 새로 | 날이 바뀌면 앱이 새 판을 연다(지금 makeToday 자리) |
| 같은 날 다시 고칠 때는 그날 문서에 덮어쓰기 | 작은 수정은 지금 판 안에서 |
| 어제 이전 판에는 쓰지 않는다 — 날짜별로 남아야 한다 | 지난 판(같은 날 앞 판 포함)은 얼려서 보존, 고치지 않음 |
| 제목 "N월N일 보고서 - N시"(시는 저장하는 실제 시각) | 판 이름 "5시", 제목 "11월 14일 보고서 - 5시" |
| 같은 날 두 번째 보관본은 _2 | 같은 시각이 겹치면 5시-1 · 5시-2 · 5시-3 (보스 지정) |
| 보스 메모가 있으면 덮기 전에 보관 | 새 판을 열 때 앞 판을 통째로(메모 포함) 얼려 둠 |
| 말풍선 — 오늘 요약 · 지금 손댈 것 · 세희가 하고 싶은 말, 말하듯이, 머리표 금지, 표정 도장 | '세희 한마디' 칸 = 그 판의 말풍선. 2~4줄(앱은 짧게), 표정 도장 |
| 세희는 완료를 찍지 않는다(보스만) | 그대로 — 끝냄은 보스 몫, 세희는 코멘트로만 |

## 2. 데이터 (판 저장 구조는 그대로, 날짜 판 안에 판 기록을 덧붙임)
```
pans[date] = { …지금 그대로(items · inbox · line · face …),
  ver:  { label:'17시', at, by:'sehee'|'app'|'boss', why:'보스가 정리하자고 함' },      ← 지금 판
  vers: [ { label:'5시', at, until, by, why, line, face, items[], inbox[] }, … ] }      ← 얼린 지난 판(최대 24개)
item.cm = '세희 코멘트 한 줄'                                                           ← 보스 메모(note)와 별개
```
- 날짜 판 하나에 다 들어가서 지금 동기화(pan:날짜)를 그대로 탄다. IndexedDB 판 구조·키는 안 바꿈(업그레이드 없음).
- ver 가 없는 옛 판은 처음 열 때 만든 시각으로 이름을 붙인다(옛 데이터 손대지 않음).
- 이름 규칙: 지금 시각의 시(0~23시). 그날 같은 시 판이 이미 있으면 그 판을 'N시-1'로 바꾸고 새 판은 'N시-2', 다음은 'N시-3'.

## 3. 새 판이 생기는 때 (이것만)
1. 날이 바뀜 — 앱이 자동(지금처럼 안 끝난 일 이어받기), 이유 '날이 바뀜'.
2. 큰 갱신 — 세희가 도구 new_report(why) 를 먼저 부르고 그 판에 쓴다:
   - 보스가 판·보고서를 정리하자·새로 쓰자고 할 때
   - 긴 캡처·문서·여러 소식을 받아 항목 여러 개를 한꺼번에 바꿀 때
3. 보스가 직접 — 판 띠의 「새 판」 단추(선택, 실수로 누르지 않게 두 번 누르기).
- 작은 수정(항목 하나 고치기 · 시각 넣기 · 메모 · 끝냄 · 한두 개 더하기)은 새 판 없이 지금 판 안에서.
- 같은 차례에 new_report 를 두 번 불러도 판은 하나만(2분 안이면 그대로 둠).

## 4. 화면
- 이름표: 서랍 머리 「🗒️ 일간보고서」, 아래 단추 「일간보고서」, 왼쪽 견출지 「보고서」(세로라 짧게). 사무실 보드의 A4 '보고서' 카드와 헷갈리지 않게, 판 쪽은 늘 '일간보고서'.
- 판 띠(날짜 줄 바로 아래 한 줄): 「📄 11월 14일 보고서 - 17시 · 지금」 + 「지난 판 2 ▾」.
  - ▾ 를 누르면 그날 판 목록(지금 판 맨 위): 이름 · 쓴 시각~다음 판까지 · 항목 수 · 이유 한 줄.
  - 지난 판을 고르면 그 판을 그대로 보여 줌 — 보기 전용(단추·입력 막힘, 흐린 '지난 판' 띠, 「지금 판으로」).
  - 다른 날로 가면 늘 그날의 지금 판부터.
- 세희 코멘트: 항목 제목·날짜 줄 아래 한 줄, 세희 서명색(작은 글씨, 앞에 '세희'). 보스 메모칸(✎ 메모)과 색·자리 구분.
- 세희 한마디: 지금 자리 그대로, 새 판을 열면 세희가 채움.

## 5. 세희 (도구·맥락·지침)
- 도구
  - new_report({why, line?, face?}) — 지금 판을 얼리고 새 판을 연다. 큰 갱신 전에만.
  - set_line({line, face?}) — 세희 한마디(2~4줄, 200자 안) + 표정 도장.
  - add_item · update_item 에 comment(한 줄 40자 안, '' 이면 지움).
  - read_pan 에 version — 그날 지난 판을 이름으로 읽기. 돌려줄 때 그날 판 목록도 같이.
- 맥락 첫 줄: 「지금 판: 11월 14일 보고서 - 17시(17:20부터, 보스가 정리하자고 함) · 오늘 지난 판: 5시」. 항목 줄에 '세희 코멘트:' 줄.
- 지침(새 묶음 하나 — C 의 판 지침 줄과 따로):
  - 판 = 일간보고서. 보스에게 말할 땐 '일간보고서'.
  - 새 판은 3장의 때만. 작은 수정은 지금 판 안에서. 지난 판은 고치지 않는다.
  - 보고서는 세희가 쓰는 문서 — 세희 목소리:
    - 한마디: 새 판을 열면 꼭, 그 뒤엔 크게 달라졌을 때만. 2~4줄, 말하듯이(오늘 핵심 · 지금 손댈 것 · 세희 생각), 머리표 금지. 표정 도장 -_- 밀린 날 · ¬_¬ 어이없는 날 · >_< 답답한 날 · T_T 급한 게 밀림 · o_O 예상 못 함 · ^_^ 잘 풀림.
    - 항목 코멘트: 판단이 필요한 몇 개에만(판의 3분의 1 이하), 한 줄 40자 안. 사실 되풀이 말고 판단·짐작·권유 — '~인 것 같아요', '~입니다', '~부터 하시면 좋겠어요'. 보스 메모칸은 보스 것이라 세희는 쓰지 않는다(지금 규칙 그대로).

## 6. 파일 구역 (C 와 나눔)
- js/base.js: emptyPan·makeToday(ver), render 맨 위 판 띠, itemRow 안 코멘트 한 줄, 새 '일간보고서 판' 함수 묶음(verEnsure·verNextLabel·newReport·보기 전용 막기). C 의 DEFAULT_SECTIONS·TAGS·처리 단추 구역은 안 건드림.

- 테스트 tests/treport.js: 새 판 이름(5시 → 5시-1·5시-2), 큰 갱신만 새 판·작은 수정은 그 판, 날 바뀜 새 판, 지난 판 보기 전용·보존, 동기화 값에 vers 포함, 세희 도구 4종·맥락 첫 줄, 코멘트 표시.
